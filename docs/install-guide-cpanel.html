📘
آشنایی و پیش‌نیازهااین راهنما برای چه کسانی است؟

کنسول جستجوی فارسی یک داشبورد کامل برای مدیریت و تحلیل داده‌های Google Search Console است — به زبان فارسی، با نمودارهای تعاملی، اعداد فارسی، تاریخ شمسی و راهنمای ساده برای مبتدی‌ها. تمام ۱۰ بخش اصلی سرچ کنسول (عملکرد جستجو، بازرسی URL، ایندکس‌گذاری، موبایل، سایت‌مپ، امنیت، نتایج غنی، لینک‌ها، Core Web Vitals و حذف‌های موقت) در آن پوشش داده شده است.

نسخه‌ای که با این راهنما نصب می‌کنید، نسخه استاتیک cPanel است: کل برنامه به‌صورت فایل‌های HTML/JS/CSS خالص تبدیل شده و مستقیماً داخل مرورگر شما اجرا می‌شود. یعنی هاست شما فقط فایل‌ها را مثل یک سایت معمولی سرو می‌کند — نه به Node.js نیاز دارد، نه به دیتابیس، نه به هیچ نصب اضافه‌ای. همین حالت، سریع‌ترین و کم‌دردسرترین راه اجرا روی هاست اشتراکی است.

✅ پیش‌نیازها — قبل از شروع این موارد را داشته باشید

  • یک هاست اشتراکی cPanel (تقریباً همه هاست‌های اشتراکی ایران و خارج cPanel دارند)
  • نام کاربری و رمز عبور cPanel (از پیام خوش‌آمد هاستینگ یا پنل کاربری هاست خود بگیرید)
  • یک دامنه یا ساب‌دامنه که به هاست شما متصل باشد (مثلاً example.com یا search.example.com)
  • حدود ۵ مگابایت فضای خالی روی هاست (بسته نهایی حدود ۲ مگابایت است)
  • نیازی به ترمینال، SSH، Node.js، PHP یا دیتابیس نیست!
💎

فلسفه این نسخه: برنامه کاملاً سمت مرورگر (Client-Side) اجرا می‌شود. در «حالت نمایشی» همه امکانات با داده نمونه فارسی بدون هیچ اتصالی کار می‌کند. برای دیدن داده واقعی سایت خودتان، در بخش ۹ همین راهنما حساب گوگل خود را متصل می‌کنید — بدون اینکه هاست شما هیچ نقشی در آن داشته باشد.

۲🔐
ورود به cPanelپنل مدیریت هاست خود

cPanel همان پنل مدیریتی است که هاستینگ به شما داده. برای ورود، در مرورگر آدرس هاست خود را همراه با پورت ۲۰۸۳ باز کنید: https://example.com:2083 — یا از دکمه «ورود به cPanel» در پنل کاربری سایت هاستینگ استفاده کنید. نام کاربری و رمز عبور معمولاً در ایمیل خوش‌آمدگویی هاستینگ ارسال شده است.

  1. Username: نام کاربری هاست (معمولاً چیزی مثل hosting_user — دقیقاً همان که هاستینگ داده).
  2. Password: رمز عبور cPanel. اگر یادتان نیست، از پنل کاربری هاستینگ «تغییر رمز cPanel» را بزنید.
  3. دکمه آبی Log in را بزنید تا وارد پنل شوید.
⚠️

اگر بعد از چند تلاش ورود ناموفق بود، بعضی هاست‌ها بعد از ۵ خطا IP شما را موقتاً بلاک می‌کنند (محدودیت cPHulk). صبر کنید یا از پشتیبانی هاست بخواهید بلاک را بردارد.

۳🗂️
پیدا کردن File Managerابزار مدیریت فایل‌های هاست

بعد از ورود، صفحه اصلی cPanel را می‌بینید که پر از آیکون‌های مختلف است. ما فقط به File Manager نیاز داریم — ابزار آپلود و مدیریت فایل. سریع‌ترین راه پیدا کردن آن، استفاده از کادر جستجوی بالای صفحه است.

  1. در کادر جستجوی بالای صفحه عبارت file manager را تایپ کنید.
  2. از نتایج، روی File Manager (زیر بخش FILES) کلیک کنید — کاشی آبی هایلایت‌شده در تصویر.

File Manager در یک تب جدید باز می‌شود و شما را در پوشه خانگی (/home/username) قرار می‌دهد. محل نصب داشبورد باید پوشه public_html باشد — همان پوشه‌ای که ریشه سایت شماست.

  1. دکمه Upload (آپلود) در نوار ابزار بالای File Manager — قدم بعدی با همین دکمه است.
  2. مسیر فعلی: home / public_html — مطمئن شوید داخل همین پوشه هستید (در درخت سمت چپ روی public_html کلیک کنید).
💡

اگر در حال حاضر فایل‌هایی مثل index.html یا wp-config.php (سایت وردپرسی) در public_html دارید، یعنی سایت فعلی روی این دامنه فعال است. در این صورت ابتدا بخش ۹ — نصب روی ساب‌دامنه را انجام دهید تا فایل‌های سایت‌تان بازنویسی نشود، بعد به همین‌جا برگردید. اگر public_html خالی است (یا فقط default.html دارد)، خیالتان راحت ادامه دهید.

۴📤
آپلود فایل ZIPهمان فایلی که در قدم ۱ دانلود کردید

روی دکمه Upload در نوار ابزار File Manager کلیک کنید. صفحه آپلود باز می‌شود که هم قابلیت کشیدن‌ورهاکردن (Drag & Drop) دارد و هم دکمه انتخاب فایل.

  1. می‌توانید فایل ZIP را مستقیماً داخل کادر Drag files here to upload بکشید و رها کنید.
  2. یا روی دکمه آبی Select Files کلیک کنید و فایل Persian-Search-Console-cPanel-v1.1.0.zip را از کامپیوترتان انتخاب کنید.

آپلود شروع می‌شود و نوار پیشرفت سبز رنگ پر می‌شود. حجم فایل کم است (حدود ۷۰۰ کیلوبایت)، پس حتی با اینترنت معمولی چند ثانیه بیشتر طول نمی‌کشد:

وقتی پیام Upload complete با تیک سبز ظاهر شد، روی دکمه Go Back to File Manager کلیک کنید تا به لیست فایل‌ها برگردید. حالا فایل ZIP باید در پوشه public_html قابل مشاهده باشد.

⚠️

اگر هنگام آپلود خطای «The file exceeds the upload_max_filesize» دیدید (در بعضی هاست‌ها سقف آپلود پایین است)، نگران نباشد: تیک Overwrite existing files را بزنید و مجدد تلاش کنید، یا از پشتیبانی بخواهید سقف آپلود را بالا ببرد. فایل ما فقط ۷۰۰ کیلوبایت است و تقریباً هیچ هاستی با آن مشکلی ندارد.

۵📂
استخراج (Extract) فایل ZIPاز حالت فشرده خارج کنید

فایل ZIP آپلودشده باید باز (استخراج) شود تا فایل‌های واقعی برنامه آزاد شوند. روی نام فایل ZIP در لیست، راست‌کلیک کنید:

  1. روی فایل Persian-Search-Console-cPanel-v1.1.0.zip راست‌کلیک کنید (در بعضی مرورگرها کلیک با نگه‌داشتن دکمه راست موس).
  2. از منوی بازشده، گزینه Extract را انتخاب کنید (در تصویر هایلایت شده).

پنجره استخراج باز می‌شود و مسیر پیش‌فرض همان پوشه فعلی (public_html) است — چیزی تغییر ندهید و تأیید بزنید:

  1. بعد از دیدن پیام سبز The archive has been successfully extracted، دکمه Close را بزنید.

حالا لیست فایل‌های public_html باید دقیقاً مثل تصویر زیر باشد — فایل اصلی index.html، پوشه _next (فایل‌های برنامه)، فایل .htaccess (بهینه‌سازی سرعت) و چند فایل دیگر:

  1. index.html — صفحه اصلی داشبورد (دقت کنید که این فایل به‌جای صفحه قبلی سایت قرار گرفته).
  2. .htaccess — تنظیمات فشرده‌سازی و کش (فایل مخفی است؛ اگر نمی‌بینید از دکمه Settings در File Manager تیک «Show Hidden Files» را بزنید).
  3. _next — پوشه اصلی برنامه (JS/CSS/فونت‌ها). این پوشه را باز نکنید و دست نزنید!
🧹

اختیاری: بعد از استخراج موفق، می‌توانید فایل ZIP را حذف کنید (راست‌کلیک → Delete) تا فضای هاشت آزاد شود. فایل default.html قدیمی هاست هم اگر هنوز موجود بود حذفش کنید.

از این لحظه، برنامه به‌طور کامل روی هاست شما اجرا می‌شود. دو راه ورود دارید:

۷🌐
سایت موجود دارید؟ نصب روی ساب‌دامنهبدون دست‌زدن به سایت فعلی‌تان

اگر روی دامنه اصلی‌تان سایت فعلی دارید (وردپرس، فروشگاه و...)، به‌جای public_html ریشه، یک ساب‌دامنه جدید بسازید و داشبورد را آنجا نصب کنید. نتیجه: داشبورد شما روی آدرسی مثل search.example.com اجرا می‌شود و سایت اصلی‌تان دست‌نخورده می‌ماند. این کار کاملاً رایگان است و هیچ تنظیم اضافه‌ای نمی‌خواهد.

در cPanel عبارت subdomains را در کادر جستجو تایپ کنید و روی نتیجه کلیک کنید:

  1. در فیلد Subdomain یک اسم دلخواه انگلیسی بنویسید (مثلاً search).
  2. دامنه اصلی خود را از منوی Domain انتخاب کنید. مسیر Document Root خودکار پر می‌شود (مثلاً /public_html/search) — چیزی تغییرش ندهید.
  3. دکمه Submit را بزنید. ساب‌دامنه در چند دقیقه فعال می‌شود.

سپس دقیقاً همان قدم‌های ۳ تا ۶ را انجام دهید، با این تفاوت که در File Manager به‌جای public_html، وارد پوشه public_html/search شوید و ZIP را همان‌جا آپلود و Extract کنید. بعد از آن داشبورد روی https://search.example.com در دسترس است.

ℹ️

چرا ریشه دامنه؟ فایل‌های برنامه با مسیرهای مطلق (شروع از /) ساخته شده‌اند، بنابراین داشبورد باید در ریشه یک دامنه یا ساب‌دامنه قرار بگیرد. نصب در زیرپوشه‌ای از سایت موجود (مثل example.com/search) پشتیبانی نمی‌شود — به‌جایش ساب‌دامنه بسازید که همان اثر را دارد.

۸🔒
فعال‌سازی SSL (توصیه‌شده)گواهی رایگان AutoSSL برای قفل سبز کنار آدرس

SSL باعث می‌شود سایت شما با https:// و قفل سبز باز شود. برای خود داشبورد اجباری نیست، اما اگر می‌خواهید داده واقعی گوگل را وصل کنید (بخش بعدی)، گوگل فقط آدرس‌های https را می‌پذیرد. خوشبختانه cPanel گواهی رایگان AutoSSL دارد که با یک کلیک فعال می‌شود.

در cPanel عبارت ssl/tls status را جستجو کنید:

  1. دکمه Run AutoSSL را بزنید. درخواست گواهی رایگان ثبت می‌شود (تا ۱۵ دقیقه طول می‌کشد).

بعد از فعال شدن، در جدول همان صفحه کنار دامنه‌تان وضعیت Certificate Active را می‌بینید و سایت با https بدون هیچ خطایی باز می‌شود. اکثر هاست‌ها AutoSSL را خودکار اجرا می‌کنند، پس ممکن است از قبل فعال باشد.

💡

اگر بعد از فعال شدن SSL هنوز با http باز می‌شود، یک بار آدرس را دستی با https باز کنید — خود برنامه و فایل .htaccess همراهش، بازدیدهای بعدی را خودکار به https هدایت نمی‌کنند تا تداخلی با تنظیمات سایت شما ایجاد نشود.

۹📊
اتصال داده واقعی گوگل (اختیاری)Google Search Console خودتان — بدون دخالت هاست

تا اینجا داشبورد با داده نمایشی کار می‌کند. برای دیدن داده واقعی سایت خودتان، برنامه مستقیماً از مرورگرِ خودتان به گوگل وصل می‌شود (Google Identity Services). تنها چیزی که لازم دارید یک OAuth Client ID رایگان از Google Cloud Console است. این بخش کاملاً اختیاری است و می‌توانید هر وقت خواستید انجامش دهید.

قدم ۱ — ساخت پروژه و رفتن به Credentials

به console.cloud.google.com بروید و با حساب جیمیل خود وارد شوید. یک پروژه جدید بسازید (منوی بالای صفحه → New Project، اسم دلخواه مثلاً search-console-app). سپس از منوی APIs & Services به بخش Credentials بروید:

  1. دکمه آبی + CREATE CREDENTIALS را بزنید.
  2. از منوی بازشده OAuth client ID را انتخاب کنید.

قدم ۲ — صفحه رضایت (Consent Screen)

اگر اولین بار است Client ID می‌سازید، گوگل از شما می‌خواهد «صفحه رضایت» را تنظیم کنید. این صفحه همان چیزی است که موقع ورود به گوگل خودتان می‌بینید. فقط چند فیلد ساده است:

  1. App name: مثلاً Persian Search Console (هر اسمی).
  2. User type: حتماً External را انتخاب کنید و Save بزنید. مراحل Scopes و Test Users را بدون تغییر با Save رد کنید تا به خلاصه برسید.

قدم ۳ — ساخت OAuth Client ID

حالا فرم ساخت Client ID را پر کنید. چون برنامه کاملاً داخل مرورگر اجرا می‌شود، فقط نیاز به «JavaScript origins» داریم — نه Redirect URI:

  1. Application type: حتماً Web application.
  2. Authorized JavaScript origins: آدرس دقیق داشبورد خودتان را با https وارد کنید (مثلاً https://search.example.com). دقت کنید: بدون اسلش آخر، بدون www اضافی — دقیقاً همان آدرسی که داشبورد با آن باز می‌شود.
  3. دکمه CREATE را بزنید.

قدم ۴ — کپی کردن Client ID

پنجره موفقیت باز می‌شود و Client ID شما را نشان می‌دهد — همان رشته طولانی که با عدد شروع می‌شود و به apps.googleusercontent.com ختم می‌شود:

  1. کل Client ID را کپی کنید (آیکون کپی کنار آن). Client Secret لازم نیست — برنامه شما کاملاً در مرورگر است و رازی روی هاست ذخیره نمی‌شود.

قدم ۵ — وارد کردن Client ID در داشبورد

به صفحه ورود داشبورد برگردید (دامنه خودتان). زیر دکمه ورود گوگل، لینک «تنظیمات اتصال گوگل (Client ID)» را بزنید:

  1. Client ID کپی‌شده را در این فیلد جای‌گذاری کنید (Ctrl+V).
  2. دکمه ذخیره را بزنید. شناسه فقط در مرورگر خودتان (localStorage) ذخیره می‌شود و به هیچ سروری ارسال نمی‌شود.

حالا دکمه «ورود با حساب گوگل» را بزنید — پنجره انتخاب حساب گوگل باز می‌شود، اجازه دسترسی بدهید و وارد داشبورد با داده واقعی سایت‌های خودتان می‌شوید! 🎉

⚠️

مهم: آدرسی که در JavaScript origins وارد کردید باید دقیقاً با آدرسی که داشبورد را با آن باز می‌کنید یکی باشد (https و بدون www اضافه). اگر «origin mismatch» خطا دیدید، برگردید به Google Cloud و آدرس درست را اضافه کنید. همچنین دامنه شما باید SSL فعال داشته باشد (بخش ۸).

ℹ️

محدودیت‌های API گوگل: بخش‌های عملکرد جستجو، سایت‌مپ‌ها، لیست سایت‌ها و بازرسی URL از API رسمی گوگل داده واقعی می‌گیرند. بعضی گزارش‌ها (مثل جزئیات نتایج غنی و Core Web Vitals) به‌خاطر محدودیت API عمومی گوگل، با داده نمایشی تکمیل می‌شوند و در خود برنامه به‌صورت شفاف مشخص شده‌اند.

۱۱🛠️
عیب‌یابی و رفع مشکلاتخطاهای رایج و راه‌حل‌های قطعی

🐞 مشکل: صفحه کاملاً سفید است

علت رایج: فایل‌ها در جای درست Extract نشده‌اند — یعنی به‌جای اینکه index.html مستقیم داخل public_html باشد، در یک زیرپوشه (مثل public_html/Persian-Search-Console-cPanel-v1.1.0) قرار گرفته است. راه‌حل: در File Manager وارد آن زیرپوشه شوید، همه فایل‌ها را Select All کنید و با Move به public_html منتقل کنید (یا پوشه‌ها را Cut و در ریشه Paste). مطمئن شوید آدرس public_html/index.html واقعاً وجود دارد.

🚫 مشکل: خطای 403 Forbidden

علت: بعضی هاست‌ها دسترسی فایل‌ها را محدود می‌کنند یا قالب (Theme) هاست شما دسترسی به فایل‌های .htaccess را بسته. راه‌حل: در File Manager روی پوشه _next راست‌کلیک → Change Permissions و مقدار 755 را بدهید؛ برای index.html مقدار 644. اگر باز هم خطا بود، نام فایل .htaccess را به htaccess.txt تغییر دهید (برنامه بدون آن هم کار می‌کند، فقط کندتر).

🔤 مشکل: فونت‌ها ناجور یا مربع‌های خالی

علت: MIME اشتباه فایل‌های woff2 روی هاست‌های خیلی قدیمی. راه‌حل: یک بار Ctrl+F5 بزنید (کش کامل). اگر حل نشد، به پشتیبانی هاست بگویید «Please add font/woff2 MIME type». در ۹۹٪ هاست‌ها این مشکل وجود ندارد.

🟡 مشکل: «ورود با گوگل» کار نمی‌کند

به ترتیب چک کنید: ۱) Client ID کامل کپی شده (شروع با عدد، پایان با apps.googleusercontent.com)؛ ۲) در Google Cloud، بخش Authorized JavaScript origins، آدرس سایت شما دقیقاً با https وارد شده؛ ۳) SSL سایت فعال است (بخش ۸)؛ ۴) پنجره‌های popup مرورگر بلاک نیستند. اگر پیام «origin mismatch» دیدید، مربوط به مورد ۲ است.

🔄 مشکل: تغییرات دیده نمی‌شود (نسخه قدیمی می‌آید)

کش مرورگر است. Ctrl+F5 بزنید یا در حالت خصوصی مرورگر باز کنید. فایل‌های JS با نام یکتا (hash) ساخته می‌شوند، پس بعد از هر به‌روزرسانی، خودکار نسخه جدید می‌آید — فقط همان بار اول کش مرورگر ممکن است مزاحم شود.

📦 مشکل: ZIP آپلود نمی‌شود

ابتدا مطمئن شوید در پوشه درست (public_html) هستید و تیک Overwrite existing files را زده‌اید. فایل ما زیر ۱ مگابایت است؛ اگر باز خطای سقف آپلود دادید، از پشتیبانی بخواهید upload_max_filesize را حداقل به ۲ مگابایت برسانند.

👀 فایل .htaccess را نمی‌بینم

طبیعی است — فایل مخفی است. در File Manager دکمه Settings (بالای صفحه) → تیک Show Hidden Files (dotfiles) → Save. حالا فایل‌های نقطه‌دار دیده می‌شوند.

۱۲❓
پرسش‌های متداولسوالاتی که همه می‌پرسند

آیا واقعاً به Node.js یا دیتابیس نیاز ندارم؟
نه! نسخه cPanel برنامه کاملاً به فایل‌های استاتیک تبدیل شده و کل منطق آن در مرورگر بازدیدکننده اجرا می‌شود. هاست شما فقط فایل‌ها را سرو می‌کند — دقیقاً مثل یک سایت HTML ساده. حتی حالت اتصال گوگل هم مستقیم بین مرورگر شما و گوگل برقرار می‌شود، بدون رد شدن از هاست.
داده‌های من کجا ذخیره می‌شوند؟ حریم خصوصی چطور است؟
هیچ داده‌ای روی هاست شما ذخیره نمی‌شود. تنظیمات (Client ID، وضعیت ورود) فقط در localStorage مرورگر خودتان است و با پاک‌کردن داده مرورگر، کاملاً حذف می‌شود. در حالت واقعی، ارتباط مستقیم مرورگر ↔ گوگل است. هیچ سرور واسط، لاگ یا ردیابی وجود ندارد — کد برنامه هم در گیت‌هاب باز است و می‌توانید خودتان ببینید.
تفاوت «حالت نمایشی» و «داده واقعی» چیست؟
حالت نمایشی داده ساختگی اما واقع‌گرایانه فارسی (۱۶ ماه روند، ۵ سایت نمونه) دارد تا همه امکانات را بدون گوگل ببینید. داده واقعی یعنی اتصال به حساب Search Console خودتان — آن وقت سایت‌های واقعی خودتان، کلیک‌ها و جایگاه‌های واقعی را می‌بینید. برنامه در هر حالت به‌صورت شفاف نشان می‌دهد کدام گزارش واقعی است و کدام نمایشی (محدودیت API عمومی گوگل).
چند نفر می‌توانند از داشبورد استفاده کنند؟
هر بازدیدکننده‌ای که آدرس را بداند، صفحه ورود را می‌بیند؛ اما داده واقعی فقط با Client ID خودش و حساب گوگل خودش باز می‌شود. اگر می‌خواهید فقط خودتان دسترسی داشته باشید، می‌توانید در cPanel از قابلیت Directory Privacy (رمزگذاری پوشه) برای public_html استفاده کنید — برنامه به آن واکنشی ندارد و کنارش کار می‌کند.
روی هاست غیر از cPanel هم کار می‌کند؟
بله — هر هاستی که فایل‌های استاتیک سرو کند: DirectAdmin، Plesk، هاست‌های ایرانی و حتی GitHub Pages یا Netlify. فقط کافی است محتوای ZIP را در ریشه سایت Extract کنید. فایل .htaccess مخصوص Apache است و روی بقیه نادیده گرفته می‌شود.
قبل از خرید هاست، می‌خواهم برنامه را تست کنم — امکانش هست؟
بله! فایل ZIP را روی کامپیوتر خود Extract کنید و فایل index.html را در مرورگر باز کنید (روی بعضی مرورگرها بهتر است با یک سرور محلی مثل افزونه Live Server باز شود). چون برنامه کاملاً سمت مرورگر است، همان‌جا هم کار می‌کند و حالت نمایشی کامل در دسترس است.

۱۳⬆️
به‌روزرسانی برنامهوقتی نسخه جدید در گیت‌هاب منتشر شد

نسخه‌های جدید با فایل ZIP جدید در صفحه Releases گیت‌هاب منتشر می‌شوند. به‌روزرسانی دقیقاً مثل نصب اول است، فقط یک نکته: چون نام فایل‌ها در هر نسخه فرق دارد، اول نسخه قبلی را پاک کنید تا فایل‌های قدیمی با جدید قاطی نشوند:

  1. در File Manager وارد public_html شوید و این‌ها را حذف کنید: فایل index.html، پوشه _next و فایل‌های favicon.svg و logo.svg (فایل‌های اختصاصی خودتان را نگه دارید!).
  2. ZIP نسخه جدید را آپلود و Extract کنید — همان قدم‌های ۳ تا ۵.
  3. مرورگر را با Ctrl+F5 رفرش کنید. تمام!
ℹ️

تنظیمات شما (Client ID گوگل و وضعیت ورود) در مرورگر خودتان ذخیره شده و با به‌روزرسانی هاست از بین نمی‌رود — نیازی به تنظیم مجدد ندارید.
